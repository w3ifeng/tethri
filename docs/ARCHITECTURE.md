# Architecture

## Desktop

`FocusCore` contains value types and a deterministic session state machine with injected monotonic time. It has no AppKit or network dependencies. `AppModel` connects the engine to the activity notifications, the single serial Chrome automation worker, enforcement, persistence, conversation transport, and rain player. `AppDelegate` owns the menu bar, dashboard, and nonactivating panels. `CompanionClient` is injected; `HTTPCompanionClient` implements the typed HTTPS contract.

Every session captures an immutable rules snapshot. Time counts only outside breaks, sleep, known distractions and unresolved questions. Neutral apps count as specified. One earned credit is held until requested, consumed immediately on break start, and never banked. The engine caps durations regardless of model wording. Ending a break discards its remainder. Model text is rendered with `Text`, not Markdown or HTML. Provider replies remain visible for all intents; a separate session-status line reports local break/access outcomes. Only locally generated status text claims permission or timing outcomes. The engine reports whether an interpretation was accepted so late replies cannot appear as successful decisions.

Captured browser resources combine bundle ID, PID, process launch date, tab ID and canonical resource. YouTube watch links and youtu.be links use an eleven-character video ID; Shorts, homepages and lookalike domains do not. Tracking and playback parameters cannot invalidate a video grant. Grants are transient. A snapshot reconciles background granted tabs while Chrome is foreground; navigating away invalidates that grant at the next observation. A navigation away and back entirely between polling intervals cannot be detected by polling.

Switching activities suspends an unresolved intervention for that exact resource, preserving its ID, reply and deadline. A bounded in-memory cache holds up to 32 suspended questions and resets with the session; none are checkpointed. Returning after its deadline follows the ordinary validated denial path, without opening another question or extending the deadline. Provider request IDs are cleared on suspension, so a stale reply cannot become valid when returning. The desktop announces each intervention once. Tethri's own windows do not clear activity, and a failed Chrome read does not replace an existing same-process browser target with an unknown app target. Resource identity and study grants remain separate from this question history.

Only the front Chrome tab is inspected normally. When lecture grants exist, transient tab metadata is also read to invalidate background grants. Polling occurs at one-second intervals only while a session is active and Chrome is foreground. Workspace notifications handle native app activation. Snapshot and close operations run on one serial utility queue. Apple Events have one-second per-event timeouts and a bounded traversal budget. A blocked Apple Event is allowed to finish; another worker is never started to bypass it. This is a best-effort deadline, not cancellation of an OS call.

Close operations enumerate tabs by ID across windows, re-read the URL, reauthorize against the live engine on the main actor, and re-read again immediately before sending the tab-specific close command. No shortcuts or current-tab operations are used. Background break expiry touches only encountered resources. App hiding checks PID, launch time, bundle ID and the current session policy, then verifies `isHidden` without force quitting. A denied app activated again is hidden again.

`mach_continuous_time` drives live timers so sleep and wall-clock changes cannot extend a break. Sleep notifications stop study accumulation and rain. A minimal UserDefaults checkpoint is refreshed every five seconds and immediately on permission transitions. It contains timing/rules/goal and encountered break targets needed for revalidation after restart, not a browsing history. This means current break target addresses may exist in the interrupted checkpoint until the session ends. Checkpoints never cause immediate unvalidated OS actions. Same-boot restart uses the saved monotonic deadline; reboot uses bounded wall-clock recovery. Study time may conservatively lose up to five seconds on an abrupt crash. No break credits are refilled by resume.

## Backend

A Node.js 24 Neon Function exposes the public HTTPS conversation endpoint. Its branch's Postgres database owns quota state in the dedicated `little_focus` schema. A transaction-scoped advisory lock serializes quota checks and increments across function instances; rejected reservations do not consume other counters. Expired counters are removed after two days. Client-generated installation IDs are hashed and used only as fairness hints; shared project limits are authoritative. No invitation or login is required. Neon injects `DATABASE_URL`; `GEMINI_API_KEY` stays in encrypted server-side function variables.

The Gemini request uses only text, structured JSON output and minimal thinking. No tools are enabled. Input and output contracts reject unknown action fields (including inside history and context), invalid enums, nonfinite durations, blank replies, oversize messages and excess context. An optional validated context object describes idle/focus/break phase, remaining break seconds, the captured intervention's app/domain label, and available study-access capability. It is independent of the current foreground label. Older clients may omit context. Exact URL, PID and tab identity never leave the Mac. Prompt injection cannot modify the session engine's allowance or invoke OS commands. A misleading lecture explanation can receive a study grant because v1 explicitly does not verify the truth of an explanation.

The provider system instruction defines Tethri's focus/accountability role and the reply behavior for each break state. A second system part is computed from the validated request by `sessionPolicy`: phase, explicit break state, remaining seconds/rounded minutes, and maximum break minutes. Only fixed enum values and bounded numbers enter this part; goals, messages, resource labels and prior replies stay in user contents. The role instructions require current policy to override bargaining and mistaken earlier advice, so the conversational reply should agree with local earned-break rules. This improves guidance; the local engine still validates and applies every permission/timing change independently of model prose.

The conversational scope is distraction accountability, not tutoring or work planning. The prompt instructs one or two short sentences capped at 240 characters, no assignment/progress questions or work-step suggestions, and no engagement questions. A narrow clarification is permitted only when necessary to determine a captured resource's relevance; an already explained lecture requires no quiz. The wire response contract remains capped at 600 characters for compatibility; the stricter short-response instruction is checked in live smoke tests.

A project and client minute/day reservation is committed before every provider attempt. Provider 429/5xx or transient network errors can retry once within the total time budget; invalid responses do not retry. Failures return machine categories for local fallback. Successful replies echo the original identifiers. The Mac ignores mismatches, obsolete interventions and responses after the deadline. In-memory recent context is derived from the last six visible messages, including session transitions, intervention questions and local policy outcomes. It stays across session transitions for continuous chat and is discarded on app exit. Routine telemetry uses an explicit allowlist of latency, attempt count, token count and error category. The handler logs only those allowlisted metrics; deployment administrators must also avoid external request-body logging.

## Presentation and audio

SwiftUI draws the original green character using native shapes. Six expression states, sparse blinks, quiet earned-credit indicator and a last-30-seconds break reminder are local. Reduce Motion and Low Power Mode suppress blinking. Nonactivating panels join Spaces and fullscreen auxiliary windows, and position recovery clamps them to visible displays. Conversation becomes key only through input interaction; automatic questions order the panel front without activating the app.

The bundled 24-second mono PCM loop is generated deterministically from original noise by `scripts/generate-rain.py`, with a crossfaded boundary. It is CC0 and requires no downloads, streaming or microphone. AVAudioPlayer loops it with one-second volume fades. Session end, system sleep, mute, pause and the optional break-pause setting are handled locally.

Pre-session conversation uses a separate ephemeral UUID through the existing typed request contract. It never calls the session engine to grant access or earn study time. Starting/resuming/ending a session cancels outstanding requests before changing the conversation identity. Pre-session response identifiers are validated locally just like active-session responses.
